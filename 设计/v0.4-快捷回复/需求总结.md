# XPremium-Helper v0.4 快捷回复

## 背景

当前快捷回复浮层已经支持内置模板、模型生成和“插入并回复”，但生成结果与 X 回复框之间没有明确的同步状态。实际使用中会出现模型文本只显示半句、生成后没有自动写入、浮层看起来重复而 X 提交后只保留一句等问题。

## 目标

- 生成完成后自动替换当前 X 回复框草稿，不自动发送。
- 同时显示模型推荐内容和 X 回复框中的实际草稿。
- 同一条内容重复应用时保持幂等，不追加第二遍。
- 对模型输出被接口截断、接口失败、写入失败和草稿被手动修改给出明确反馈。
- 保留用户自定义的 HTTPS 兼容接口，不绑定固定模型。

## 范围

包含模型返回解析、输出截断识别、编辑器草稿写入、自动插入、候选与实际草稿对照、重新生成、插入并回复、浅色和深色主题适配、相关测试和设计参考。

不包含固定模型接入、自动发送、批量回复、私信回复、服务端代理和 Supabase/Postgres 数据存储。

## 交互决策

- 生成按钮文案为“生成并插入”，生成成功后只写入当前回复框。
- 已绑定回复框时，点击预置回复直接替换当前草稿；未绑定时先保留候选。
- 写入动作替换已有草稿，文本已经一致时不再触发第二次输入。
- “重新写入”只在用户手动改过草稿或写入失败时使用。
- “插入并回复”先确保草稿与推荐内容一致，再点击明确识别到的 X 原生回复按钮。
- 找不到原生回复按钮时保留草稿，不发送。
- 浮层分别展示“AI 推荐内容”和“X 当前草稿”。
- 长文本在独立滚动区域中完整显示，不使用单行省略隐藏正文。

## 技术约束

- 继续使用 OpenAI Chat Completions 兼容请求格式。
- `finish_reason: "length"` 转换为可读错误，提示模型输出已截断。
- 模型提示词要求一到两句、完整结束、只输出回复正文。
- 输出上限调整为 240 tokens，候选文本仍限制在 1000 字符以内。
- 编辑器命令使用编辑器所属 `Document`，补发 `input` 事件前先确认原生命令没有实际写入。
- 真实 X 只做编辑器识别、草稿写入和原生按钮识别验证，不发送真实回复。
