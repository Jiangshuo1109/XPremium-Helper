XPremium-Helper v0.4 快捷回复全状态

浮层贴近 X 原生回复框，分别展示 AI 推荐内容与 X 当前草稿。

页面状态

正常
模板列表和当前回复框可用。
生成中
生成按钮显示“生成中…”，不能重复请求。
自动写入
推荐内容与 X 草稿一致，显示“已与推荐内容一致”。
草稿被修改
X 当前草稿与推荐内容不同，提示已被手动修改。
空态
未绑定回复框时只能选择预置回复，模型生成不可用。
多编辑器
无法确认当前回复框时不写入、不发送。
模型截断
接口报告输出达到长度上限，提示提高输出长度或更换模型。
接口失败
分别显示 Key 无效、权限拒绝、限流、超时和 JSON 错误。
写入失败
保留推荐内容，提示重新选择回复框，不点击发送。
发送不可用
保留草稿，没有明确的 X 原生回复按钮时不发送。

Toast 与状态提示

当前浮层只显示一条就地状态提示，成功或同步状态保留在面板内，接口和写入错误使用红色文字并持续到下一次操作。生成、写入和发送过程中相关按钮禁用。

边界情况

  • 长文本在推荐区和草稿区独立滚动，保留换行。
  • 同一候选已经存在于 X 编辑器时直接视为成功，不再次触发 input。
  • 生成结果超过 1000 字符时只保留前 1000 字符；接口明确返回 length 截断时直接报错。
  • 页面切换、回复对象变化或编辑器失效时清空当前候选并重新绑定。

交互行为规则

触发用户操作系统行为反馈
回复框可识别点击或聚焦绑定唯一可用编辑器，读取作者和留言显示浮层
预置回复点击模板生成候选，不调用模型接口显示“预置回复已准备好”
模型生成点击“生成并插入”发送当前留言上下文，成功后替换 X 当前草稿显示推荐文本和实际草稿
重复写入点击“重新写入”候选与草稿一致时不追加、不重复触发输入保持“一致”状态
草稿变化用户在 X 回复框编辑重新读取草稿并与候选比较显示“已被手动修改”
发送点击“插入并回复”确认编辑器和原生回复按钮后点击一次发送成功后关闭浮层
发送条件不足缺少原生回复按钮保留草稿，不调用点击显示“没有找到可确认的 X 回复按钮”
页面变化切换帖子或刷新清空候选和绑定关系重新识别当前编辑器
