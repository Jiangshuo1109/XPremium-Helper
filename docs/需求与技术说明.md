# 需求与技术说明

当前公开预览版为 0.2.1，运行行为沿用 0.2.0，本次增加开源文档、作者入口和发布维护流程。历史版本段落保留原始背景；数据保留以根目录 PRIVACY.md 为准。

## 使用场景

目标用户在 X 首页、帖子详情、评论、私信及群聊发言者头像处，希望直接关注某个账号。核实后入口常驻头像下方。已关注且未确认互关时显示「取关」；已确认互关显示「蓝朋友」标签。用户明确选择「核实后才显示」，因此不能为覆盖率而推断陌生人的关系。当前实现范围与未完成项见验证记录。

## 模块与接口

- `adapter`：解析当前登录账号、头像、原生关系控件；输出 `Avatar[]` 和按 handle 索引的 `Evidence`。
- `RelationFact`：独立记录页面已经明确给出的关系、对方是否关注当前用户、蓝 V 状态和来源。关系事实不要求当前节点同时存在可点击控件。
- `Evidence.relationship`：`not-following`、`following`、`requested`；没有证据即为 `unknown`。`followsYou` 为 true / false / null，只有同一账号资料卡的明确正向或负向标记才能产生布尔值；标记缺失是 null。
- `action`：再次校验账号、节点和状态后，只点击一次对应原生按钮；观察最多 8 秒，明确的已关注、未关注或请求已发送状态持续 1.2 秒才反馈结果。
- `controller`：协调开关、DOM 更新、重复头像、节点复用、登录账号变化和页面路由变化。
- `task`：为群聊外部资料页操作建立 30 秒、单次执行的任务；优先 session，失败时回退 local。过期在读取时检查，不保证到点物理删除。
- `view`：Shadow DOM 隔离样式，以头像实时坐标定位小按钮。聊天头像列增加可清理的 25px 占位，为按钮留空间。
- `native-card`：串行触发原生悬浮交互，通过 DOM 更新事件等待明确关系；不发送私有 API 请求、不读取 Cookie。点击时重新核实，不点击缓存的失效节点。
- `probe-queue`：对已挂载蓝 V 作者去重、限制队列长度，优先可视区域并预检查下一屏。控制器维护暂停、失败与预读记录以及一分钟关系缓存。
- `worker`：设置 `chrome.storage.session` 的内容脚本访问级别。没有业务网络逻辑。
- `reply-shortcut`：委托监听真实 Enter 键，只触发与当前单编辑器共属一个区域且文案明确为发帖或回复的按钮。保留 Shift+Enter、组合输入和提及选词，限制重复触发。

## 识别约束

原生按钮需要同时具备数字账号 ID 形式的 `data-testid`、明确的关注语义、可确认的 handle、可用且可见的 DOM 节点。普通正文中的「关注我」或「关注了你」不能成为证据。

关注与回关执行的是同一种原生操作。`requested` 不能误报为已关注。多个控件对同一账号状态有冲突时，丢弃该账号的关系证据。每次点击都重读证据，不沿用失效节点。

取关必须先经过扩展的账号确认对话框。若 X 还有原生确认，只能点击新出现的、标题明确包含同一账号的取关确认按钮；找不到或身份不匹配时停止自动推进，保留原生入口。确认前再次核验单向关注条件，避免关系已变成互关后继续取关。

X 资料卡通常只提供「正在关注」，不一定提供明确的反向关系标记；未看到「关注了你」时按「未确认互关」处理并显示取关。该判断只用于提供人工确认后的取关入口，不等于服务端关系证明。

运行中的关系缓存存在页面内存，面板摘要另行写入 session，失败时回退 local；设置与冷却时间存入 local。切换路由、丢失当前账号、切换账号或关闭开关后，中止观察并移除按钮。已发给 X 的操作无法撤回，扩展不会在取消观察时执行取关。

账号变化时将旧原生控件标记为不可用，直到 X 创建新的控件节点；不会把旧 DOM 上的关注关系归给新账号。若 X 原地复用节点，按钮会保持隐藏，刷新页面后重新判断。

0.1.1 逐个尝试触发当前可见头像的原生悬停交互，成功后保存短时关系快照，不要求资料卡一直打开。点击时重新打开并核对控件。每个账号每次路由只尝试一次失败读取，不连续重试；不解析 React 私有状态、不拦截网络响应。自动读取可能短暂展示资料卡，实站目前仅部分验证。

## 页面适配边界

帖子只取主作者头像，避免引用帖里的图片或账号混入。首页、标准帖子详情和个人资料的「关注者／正在关注」列表启用；搜索、个人主页、推荐列表本身不额外注入。关注者列表按 `UserCell` 中唯一的个人头像和主页链接识别。

新版 `/i/chat` 发言者头像已确认处于 open ShadowRoot 内的独立头像列，按其个人主页链接识别，排除正文和转发卡片。只有头像区域明确提供 `data-xfh-relationship`、`data-xfh-follows-you` 或 `data-xfh-blue` 等页面关系字段时，才可在没有原生控件的情况下显示外部资料页入口；字段缺失时继续隐藏。新版会话列表和顶部仍待适配，不能从会话 ID 猜账号。

头像尺寸小于 32px、下方空间不足、超出视口时不展示。颜色按所在区域背景选择，不单靠操作系统深浅色设置。按钮用文本是因为「关注」「回关」本身是用户要区分的操作。

## 安全与错误行为

页面合成的点击事件不会触发快捷关注；只有真实用户输入进入生产操作路径。点击后锁定同一账号的所有入口。失败不重试、不排队，保留原生页面提示；弹窗设置读写失败要显示错误。

X 可能先乐观更新界面再回滚。本扩展只确认页面状态，不具备服务端最终一致性证明。实机验收必须检查网络失败时是否存在延迟回滚。

## 0.1.2 历史调整

关注、回关仅面向能明确识别为蓝 V 的帖子作者；通过作者名称区域的账号链接和蓝色认证图标交叉核实，避免借用引用帖的徽章。关注蓝色、回关金色、取关红色。取关不受蓝 V 限制，仍要求明确知道对方未关注当前用户。

后台读取原生资料卡时，在文档与已知聊天 ShadowRoot 注入临时裁剪样式，保持关系控件可读取。已有资料卡不遮挡；真实指针或键盘输入优先，中止本次读取。只针对已知 HoverCard 标识，不全局隐藏对话框或弹层。最终点击操作仍使用原生控件并重新核实身份。

单账号关系缓存有效一分钟，站内切换帖子复用；登录账号变化时清空。只读失败最多补一次，操作失败不重试。详情头像预留按钮的下方间距，移除按钮时恢复原间距。

Enter 同时支持单编辑器的发帖和回复；Shift+Enter 换行，输入法组合输入、提及候选、禁用按钮、多编辑器串帖和未知发送控件不触发。

后续行为以 0.1.3 调整为准。

## 0.1.3 当前调整

已确认互关时显示“蓝朋友”文字标签，没有按钮语义、点击监听或焦点入口。原有关注/回关仍要求蓝 V；互关标签和明确单向关注的取关入口不另外要求蓝 V。

从当前已挂载作者建立至多 20 个去重候选，优先可视范围，再只读预检查下一屏。预检查失败仅标记已预读，用户滚动到该账号后仍可正常尝试。用户交互中断不计为读取失败，空闲后继续。无自动滚动、自动翻页、批量关注或外部 AI 判断。

自动与手动资料卡的明确关系进入同一短期缓存；原生证据冲突时移除缓存。操作中的乐观状态不写入缓存，结果核实后才保留。点击立即反馈阶段，并等待后台资料卡清理，避免竞态关闭正在操作的资料卡。MutationObserver 与路由心跳会处理 X 单页跳转后异步挂载的关注者列表，但无法加速 X 的网络请求。

本节为当前版本约定，覆盖历史版本的互关隐藏与中断次数规则。
